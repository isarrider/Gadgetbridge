# Galaxy Watch7 — Data Layer protocol reference

Compact reference for the protocol implemented in
`service/devices/galaxywatch7/WearDataLayerProtocol.java`. It was derived from btsnoop captures of
the stock Samsung companion and from the decompiled Samsung plugin; none of it uses a Samsung or
Google account. For user-facing setup see [GALAXY_WATCH7_SETUP.md](GALAXY_WATCH7_SETUP.md).

## Transport

- Classic Bluetooth RFCOMM, service UUID `5e8945b0-9525-11e3-a5e2-0800200c9a66`. Pairing is a plain
  Android bond.
- Framing: `[4-byte big-endian length][protobuf envelope]`, one envelope per message
  (`MAX_FRAME_LEN` 1 MiB in the reader). Socket reads do not align to messages; the reader buffers.
- The connection is **bidirectional**: right after the phone connects, the watch connects back to
  two RFCOMM services on the phone and tears the Data Layer down within ~100 ms if nobody listens.
  `GalaxyWatch7DeviceSupport` therefore runs RFCOMM servers (with SDP records) for
  `fafbdd20-83f0-4389-addf-917ac9dae5b2` (WearProxy) and `cee50b63-5f79-4727-8b5d-504eb07e1e22`
  (WearHelper) and keeps the accepted sockets open. Their payload (WearProxy is the watch's
  TCP-over-Bluetooth proxy) is not interpreted, and only the paired watch is accepted.

## Envelope

```
Envelope
  1  payload   message; inner field number selects the type:
                 7 NodeInfo, 8 SeqAck/peer-sync, 9 DataItem, 10 MessageEvent
  2  requestId string, 27 chars, random base64url
  3  flag      varint, 1
  4  flag      varint, 1
  5  flagC     varint; 3 on peer-sync/DataItem, 5 on asset-grant, absent on NodeInfo
```

## Session handshake

1. Phone sends **NodeInfo** (`{1: nodeId, 2: name, 3: epoch, 7: connectionId}`). The watch answers
   with its own NodeInfo; its field 1 is the watch node id and field 7 a shared connection id,
   which is stored and echoed in the NodeInfo of the next connect.
2. Phone sends a **SeqAck / peer-sync** (payload field 8): a list of `{nodeId, counter}` entries
   for `cloud`, the phone node and the watch node. A malformed or missing peer-sync makes the
   watch drop the channel after ~100 ms. When the watch node id is cached it is sent bundled with
   the NodeInfo.
3. The watch's own peer-sync reports, per node, the data version it holds. DataItems we author must
   carry a `seq` above the counter the watch holds for our node, or they are silently ignored
   (`parsePeerSyncNodeCounter`, used to seed `ownDataVersion`).

## Enrollment

A watch that never completed the stock setup wizard drops every peer. It remembers the node id of
the phone that enrolled it and rejects other ids ("Mismatched node is attempting to connect"). That
id is generated by Google Play services and is not readable from the phone, so the user supplies it
once (see the setup guide). Gadgetbridge then publishes the two DataItems the stock flow produces:
`pairing/public_key` (an EC public key, generated once) and `enrolled`, authored under the GMS
package identity. The package/signature pairs used for authoring live in
`GalaxyWatch7DeviceSupport` (`GMS_*`, `SETTINGS_SOURCE_*`) and are public values of the stock apps.

## DataItems (field 9) and MessageEvents (field 10)

DataItems live at `wear://<node>/<path>` with a protobuf DataMap value and the per-node version
`seq`. MessageEvents carry a path and raw bytes (JSON or protobuf).

| Feature | Mechanism |
|---|---|
| Settings write | DataItem `w_module_sec_watch_setting/<sub>` with DataMap `{valueKey, from:"mobile"}`; value keys `booleanIsChecked`, `intLevel`, `intSelectedItem`, `stringMode`. Authored as the Watch7 plugin identity. |
| Settings read | Same paths, received from the watch; reflected into the settings UI. List settings are pushed with their option labels. |
| Notifications | DataItem `/bridger/stream_item:<node>:<pkg>:<id>:<tag>`; delete = DataItem delete. Colour is int32. Dismissals on the watch arrive as deletes. |
| Actions / quick reply | `wearable_actions` array in the notification DataMap; the watch answers on `/bridger/rpc`, we ack with `/bridger/result`. |
| Icons | Wear Asset chunks (12215 bytes each) preceded by an **asset grant** envelope (flagC 5) that authorises the receiving apps by asset digest (SHA-1, base64url, unpadded). Without the grant the watch ignores the asset. |
| Battery | DataItem `.../batterystate/data/batterystate` (level field 1, status 5, timestamp 7; the newest timestamp wins, stale nodes also publish it), plus polling via `/w_stf` `stf_battery_req` → `stf_battery_rsp`. |
| Media | Now-playing JSON on `/w_apps_media_controller/*`; control via the `/adaptive_media_bridging/rpc/*` RPC (`media_update`, subscribe token, commands). |
| Find my watch | JSON MessageEvent on `/w_apps_find_my_watch`. |
| Incoming call | Display-only call-category notification; answer/decline is handled by the normal Bluetooth call profile. |

## Not supported

Health and fitness data (handled elsewhere), workouts, and any custom watch UI.
